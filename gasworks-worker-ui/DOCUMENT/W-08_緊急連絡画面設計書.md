# W-08: 緊急連絡画面設計書

## 1. 概要
現場作業中に発生した事故、急病、トラブル等の緊急事態を本部に即座に通報するための画面です。
作業員の現在地（GPS）を自動的に取得し、最小限の操作で迅速に通報することを目的とします。

## 2. 画面レイアウト案

- **ヘッダー**: `layout/base.html` を継承（「緊急通報」のタイトルを表示）
- **状態表示エリア**: 位置情報の取得状況（「取得中...」「取得完了」など）を表示
- **メッセージ入力エリア**: 状況を簡潔に伝えるためのテキストエリア（任意入力）
- **通報ボタン**: 視認性の高い巨大な赤色ボタン
- **キャンセルボタン**: メニュー画面に戻るためのリンク

## 3. 画面項目定義

| 項目ID | 項目名 | 表示形式 | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| L-01 | GPSステータス | テキスト | 現在地の取得状況を表示 | 取得失敗時はエラーを表示 |
| I-01 | メッセージ | テキストエリア | 負傷、故障、火災などの状況を任意入力 | プレースホルダに例を表示 |
| B-01 | 緊急通報送信 | ボタン | 通報を実行する（赤色） | 1タップで実行可能にする |
| B-02 | キャンセル | リンク | 業務メニュー画面（W-02）へ戻る | 誤操作時の戻り導線 |

## 4. 機能詳細

### 4.1. 位置情報の取得
- 画面ロード時にブラウザの `Geolocation API` を呼び出し、緯度・経度を取得する。
- ユーザーが位置情報の利用を拒否した場合、または取得に失敗した場合は、その旨をステータス欄に表示し、メッセージのみで送信可能とする（緯度・経度は null を送信）。

### 4.2. 通報処理
- 「緊急通報送信」ボタン押下時、取得済みの緯度・経度と入力されたメッセージを `POST /api/emergency` へ送信する。
- 二重送信防止のため、送信中はボタンを非活性（Disabled）にする。

### 4.3. 送信完了後の挙動
- 送信成功時：トースト通知等で「通報を完了しました」と表示し、自動的に業務メニュー画面（W-02）へ遷移する。
- 送信失敗時：エラーメッセージを表示し、再試行を促す。

## 5. 連携API

### POST /api/emergency
詳細は `gasworks-api\DOCUMENT\API仕様書.md` を参照。

#### リクエストパラメータ (JSON)
```json
{
  "latitude": 35.681236,
  "longitude": 139.767125,
  "message": "現場で転倒し自力での移動が困難です。"
}
```

## 6. UI/UX上の配慮
- **操作性**: 怪我やパニック状態を想定し、各ボタンはスマートフォンの画面下部に大きく配置（`btn-xl` クラスの適用）。
- **配色**: 心理的な警告色である赤（`btn-danger`）を使用。
- **フィードバック**: 位置情報が正しく取得できているか、バイブレーション（可能であれば）やアニメーションでユーザーに安心感を与える。

## 7. 注意事項
- インメモリDBを使用しているため、サーバー再起動後は通報履歴（本部の受信ログを想定）はリセットされる。
- 本画面はオフライン時は機能しないため、ネットワーク切断時は電話での連絡を促すメッセージを併記する。
