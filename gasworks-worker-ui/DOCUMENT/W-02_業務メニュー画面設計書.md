# W-02: 業務メニュー画面設計書

## 1. 概要
ログイン後のメインポータルとして、各業務機能への導線を提供する画面です。
タイル形式のレイアウトを採用し、APIから取得した「未読数」や「残り作業数」をバッジとして表示することで、作業員が現在の状況を一目で把握できることを目的とします。

## 2. 画面レイアウト案

- **ヘッダー**: `layout/base.html` を継承（「業務メニュー」のタイトルを表示）
- **インフォメーションエリア**: 作業員名と現在の時刻を表示
- **メニュータイルエリア**: 以下のボタンをタイル状（2列表示推奨）に配置
  - **検針業務**: 残りの作業件数をバッジ表示
  - **ルートマップ**: 地図画面への遷移
  - **お知らせ**: 未読メッセージ数をバッジ表示
  - **日報作成・同期**: 作業進捗率を表示
  - **緊急連絡**: 赤色の目立つボタン
  - **個人設定**: プロフィール確認
- **フッター**: ログアウトボタンを配置

## 4. 機能詳細

### 4.1. リアルタイム情報の取得（バッジ更新）
- 画面ロード時に以下のAPIを非同期で呼び出す。
  - `GET /api/assignments/summary`: 全体数から完了数を引いた「残り件数」を計算し、検針業務タイルのバッジに反映。
  - `GET /api/notifications`: `isRead` が `false` の件数を集計し、お知らせタイルのバッジに反映。

### 4.2. 画面遷移
- 各タイルをタップすることで、対応する各機能画面へ遷移する。

## 5. 連携API

### GET /api/assignments/summary
作業進捗（残り件数の計算用）を取得。

### GET /api/notifications
お知らせ一覧（未読件数の集計用）を取得。

## 6. UI/UX上の配慮
- **視認性**: モバイル端末での片手操作を想定し、ボタン（タイル）のサイズを大きく確保（タップ領域の最大化）。
- **直感的なバッジ**: 数字が入ったバッジは、背景色を変えて強調する（例：通知は赤、作業残は青）。
- **ホーム画面としての役割**: どの画面からもヘッダーロゴ等を通じてこの画面に戻れるようにし、迷子にならない設計とする。

## 7. 注意事項
- インメモリDBのため、再起動後はバッジの数字も初期状態（全件未完了など）に戻る。
- API通信に失敗した場合は、バッジを表示しないか「-」と表示し、アプリ全体の動作を妨げないように制御する。
