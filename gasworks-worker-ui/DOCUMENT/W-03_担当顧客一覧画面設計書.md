# W-03: 担当顧客一覧画面設計書

## 1. 概要
本日の検針ルートおよび対象顧客を確認するためのメイン画面です。
作業員は当日の訪問先をリスト形式で確認し、各顧客の検針ステータス（未完了/完了）を把握することを目的とします。

## 2. 画面レイアウト案
- **ヘッダー**: `layout/base.html` を継承（「GasWorks Worker」ロゴ、お知らせバッジを表示）
- **タイトルエリア**: 「本日（YYYY/MM/DD）の検針」を表示
- **顧客リストエリア**:
  - 顧客ごとにカード形式で表示
  - 上部に「顧客名」と「ステータスバッジ」
  - 中央に「住所」
  - 下部に「検針を開始する」ボタン
- **フッター**: なし（リストが長い場合はスクロール）

## 3. 画面項目定義
| 項目ID | 項目名 | 表示形式 | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| L-01 | 顧客名 | テキスト | 検針対象の顧客氏名を表示 | |
| L-02 | 住所 | テキスト | 顧客の住所を表示。地図アイコンを付与 | |
| S-01 | ステータス | バッジ | 検針の進捗状態を表示 | 未完了：黄色、完了：緑色 |
| B-01 | 検針を開始する | ボタン | 該当顧客の検針データ入力画面（W-04）へ遷移 | 完了済みの場合は「検針済み」として非活性化 |

## 4. 機能詳細
### 4.1. 一覧表示
- 画面起動時、`GET /api/assignments` を呼び出し、ログイン中の作業員に割り当てられた当日分のデータ（scheduledDateが当日）を一覧表示する。
### 4.2. ステータスによる出し分け
- `status` フィールドの値に基づき、バッジの色とボタンの状態を切り替える。
  - `PENDING`: 「未完了」バッジ、ボタン活性
  - `COMPLETED`: 「完了」バッジ、ボタン非活性（ラベル「検針済み」）
### 4.3. 画面遷移
- 「検針を開始する」ボタン押下時、その割当ID（assignmentId）を保持して W-04 へ遷移する。

## 5. 連携API
### GET /api/assignments
詳細は `gasworks-api\DOCUMENT\API仕様書.md` を参照。

#### レスポンスデータ例 (JSON)
```json
[
  {
    "id": 501,
    "scheduledDate": "2024-10-27",
    "status": "PENDING",
    "customer": {
      "id": 101,
      "name": "山田 太郎",
      "address": "東京都千代田区..."
    }
  }
]
```

## 6. UI/UX上の配慮
- **直感的な視認性**: 未完了の作業が目立つよう、バッジの色使いに配慮する。
- **モバイルファースト**: 現場で立ちながら操作しやすいよう、カード全体をタップしやすく、ボタンを大きく配置する。

## 7. 注意事項
- インメモリDBを使用しているため、サーバーを再起動すると検針ステータスもリセットされる。
- 割当がない場合は「本日の作業割当はありません。」というメッセージを表示する。
