# W-01: 作業員ログイン画面設計書

## 1. 概要
作業員が業務を開始する際に、本人認証を行うための画面です。
正しいメールアドレスとパスワードを入力することでJWT（JSON Web Token）を取得し、セキュアな業務セッションを開始することを目的とします。

## 2. 画面レイアウト案

- **ヘッダー**: システムロゴ（GasWorks）を中央に配置
- **ログインフォームエリア**:
  - メールアドレス入力フィールド（アイコン付き）
  - パスワード入力フィールド（伏せ字、表示切替ボタン付き推奨）
- **操作ボタンエリア**: 画面中央に大きく配置された「ログイン」ボタン（青色）
- **フッター**: バージョン情報やコピーライトを表示

## 3. 画面項目定義

| 項目ID | 項目名 | 表示形式 | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| I-01 | メールアドレス | テキスト入力 | 登録済みのメールアドレスを入力 | `type="email"` 指定 |
| I-02 | パスワード | パスワード入力 | ログインパスワードを入力 | `type="password"` 指定 |
| B-01 | ログイン | ボタン | 入力内容を認証APIへ送信する | 送信中はローディング表示 |
| L-01 | エラーメッセージ | テキスト | 認証失敗時やバリデーションエラーを表示 | 赤色で表示 |

## 4. 機能詳細

### 4.1. バリデーション
- 未入力チェック: メールアドレス、パスワード共に必須項目。
- 形式チェック: メールアドレスが正しい形式であることを送信前に確認する。

### 4.2. 認証処理とトークン保持
- 「ログイン」ボタン押下時、`POST /api/auth/login` を実行する。
- 認証成功時、レスポンスに含まれる `token` (JWT) をブラウザの `localStorage` またはセッション管理用の Cookie に保存する。
- 保存完了後、自動的に業務メニュー画面（W-02）へ遷移する。

### 4.3. ログイン状態の維持
- アプリ起動時、有効なトークンが保持されている場合はログイン画面をスキップし、直接業務メニューを表示する。

## 5. 連携API

### POST /api/auth/login
詳細は `gasworks-api\DOCUMENT\API仕様書.md` を参照。

#### リクエストデータ例 (JSON)
```json
{
  "email": "worker@example.com",
  "password": "password123"
}
```

## 6. UI/UX上の配慮
- **入力補助**: メールアドレスフィールドにフォーカスした際、モバイル端末で英字キーボードが自動展開されるように設定。
- **エラー表現**: 「パスワードが違います」といった具体的な理由はセキュリティ上避けつつ、「認証に失敗しました」等の明確なフィードバックを行う。

## 7. 注意事項
- インメモリDBを使用しているため、サーバーを再起動すると初期データ以外のユーザーではログインできなくなる点に注意する。
