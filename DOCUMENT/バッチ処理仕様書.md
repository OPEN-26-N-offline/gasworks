# バッチ処理仕様書

## 1. 概要

本仕様書は、Spring Bootで実装・実行するバッチ処理の仕様を定義します。
バッチ処理は、APIサーバーと同じプロジェクト内に `@Scheduled` アノテーションや `Spring Batch` を用いて実装します。

## 2. バッチ処理一覧

### 2.1. 月次レポート生成バッチ

- **ID**: `monthlyReportBatch`
- **説明**:
  - 全顧客の当月の検針データを集計し、月次レポートを作成する。
  - 生成したレポートは、管理者へのメール通知や、特定のストレージ領域への保存を行う。
- **実行タイミング**:
  - 毎月1日の午前3時00分に実行。
  - Cron形式: `0 0 3 1 * ?`
- **実装方法**:
  - `@Scheduled` アノテーションを利用したシンプルなスケジューリング。

### 2.2. 長期間未検針アラートバッチ

- **ID**: `longTermNoReadingAlertBatch`
- **説明**:
  - 最終検針日から一定期間（例: 3ヶ月）以上経過している顧客を抽出する。
  - 抽出した顧客リストを管理者にメールで通知し、確認を促す。
- **実行タイミング**:
  - 毎週月曜日の午前5時00分に実行。
  - Cron形式: `0 0 5 ? * MON`
- **実装方法**:
  - `@Scheduled` アノテーションを利用。

### 2.3. データベースバックアップバッチ

- **ID**: `databaseBackupBatch`
- **説明**:
  - データベース全体の論理バックアップ（mysqldumpなど）を取得する。
  - バックアップファイルは、日付を付けて特定のディレクトリに保存する。
- **実行タイミング**:
  - 毎日午前2時00分に実行。
  - Cron形式: `0 0 2 * * ?`
- **実装方法**:
  - Springから外部コマンド（`mysqldump`）を実行するシェルスクリプトを呼び出す。
  - **注**: この処理は、インフラ側の機能（例: AWS RDSのスナップショット機能）で代替することも検討する。
